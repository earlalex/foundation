Platform Documentation & Setup Guide

Welcome to the technical specification and onboarding manual for the Foundation Business OS. Learn about our zero-build architecture, database structures, media pipelines, and global deployment rules.

1. Platform Overview

Foundation is a highly optimized, custom Zero-Build JAMstack Platform and business-oriented Operating System (OS). It enables developers, agencies, and business owners to deploy fully fledged web applications, high-performance physical or digital e-commerce storefronts, student portals, and automated backoffice routines directly onto serverless edge infrastructures.

By eliminating compile-time bundle overheads and relying strictly on standard native browser APIs, Foundation delivers absolute speed to both end users and development teams alike.

Core Capabilities Matrix:

  • ⚡ Zero-Build Architecture: Production deployment with zero bundling, build pipelines, or dev compile steps.
  • 🛍️ Hybrid E-Commerce: Scalable catalog for physical goods with real-time stock reservation alerts.
  • 🔐 Zero-Trust Database: Fully audited localized and remote Firestore endpoints built on dynamic permission sets.
  • 🎬 Media Portal: In-house native audio streaming, video player gates, and masonry picture galleries.

2. Architecture & Philosophy

Modern web development is too often bogged down by heavy toolchains, complex build steps, and oversized dependencies. Foundation takes a contrarian, sovereign approach by returning to the core of standard web standards:

Vanilla ES Modules

Every JavaScript module inside the framework is loaded natively via browser ES module syntax. Unbundled dependencies, direct paths, and dynamic browser imports mean instant local updates and zero cold starts.

Native Web Components

UI widgets (e.g., CTA Blocks, Hero Banners, Radio stream, etc.) are implemented utilizing standard Custom Elements and shadow DOM. This guarantees isolation, zero layout shifts, and standard-compliant rendering.

Client-Side SPA Routing

Our core router processes URL requests cleanly entirely in the client-side session context, serving templates dynamically without full page requests or navigation jank. Transitions are handled instantly with zero flicker.

Cloudflare Workers Edge

Dynamic routes, APIs, and microservices run directly on Cloudflare Workers edge serverless instances. By keeping business logic geographically proximal to end-users, we eliminate connection latencies and server overhead.

3. Setup & Environment Variables

Configuring your Foundation Business OS instance takes only a few minutes. If the system is not yet configured, launching the root application path will automatically invoke the integrated Master Onboarding Wizard.

Wrangler & Cloudflare Page Variables

Before spinning up your serverless instance, set up the required environment variables in your local wrangler.json or your Cloudflare Pages dashboard settings:

// System Environment Bindings Matrix
FOUNDATION_INSTALLED: "true",
FIREBASE_PROJECT_ID: "your-firebase-project-id",
FIREBASE_API_KEY: "AIzaSyYourApiKeyHere",
FIREBASE_AUTH_DOMAIN: "your-project.firebaseapp.com",
STRIPE_SECRET_KEY: "sk_live_...",
STRIPE_WEBHOOK_SECRET: "whsec_...",
VIRUSTOTAL_API_KEY: "vt_api_..."

Database Initialization

Foundation uses Firebase Firestore for metadata persistence and global content delivery. To secure your database from unauthorized reads and writes, the database establishes a strict Zero-Trust db boundary. You must copy the firestore.rules file from the root directory directly to your Firebase Console settings.

4. Media & Streaming Suite

The system comes out-of-the-box with a high-performance, responsive media suite utilizing standard HTML5 capabilities:

  • Instagram-Style Photo Gallery (<photo-gallery>): Masonry layouts designed using custom CSS grids. Implements responsive image display, dynamic lazy loading optimization (`lazyLoader.js`), overlay engagement stats, and localized social sharing dispatches.
  • YouTube-Style Video Portal (<video-library>): Enables hosting HLS, MP4, or YouTube video catalogs. It supports a programmatically adjustable, client-side guest paywall timeout lock: guests are prompted to register or upgrade to premium memberships when video previews expire, while administrators and paid members skip gates automatically.
  • 24/7 Web Radio Stream (<radio-stream-player>): Sticky continuous audio broadcaster mounted completely outside the single-page application SPA navigation container (`index.html`). Users can browse, navigate routes, and complete actions without interrupting stream play. Admin can configure stream feeds and toggle active queue settings from the Admin Control Center.

5. Universal Royalty Engine & Splits

Our custom-engineered Universal Royalty Splits Engine (managed inside core/royalties.js) is designed to model and enforce contributor equity payout structures across physical or digital media products:

Engine Rules & Invariants:

  • Sum-to-100% Invariant: Multi-contributor allocation rules are evaluated strictly. The sum of splits configured must equal exactly 100% during validation.
  • Admin Fallback Rule: For any asset or product purchased without a specified royalty structure, allocation falls back to 100% System Admin automatically.
  • FX & Crypto Rates Logs: Calculates multi-currency settlement splits natively, with rates logged with crypto exchange reference points.

6. Stripe & Web3 Crypto Payments

Foundation handles monetization using a dual-gateway system supporting Stripe and Web3 crypto checkouts.

Stripe Configuration

Set up Stripe product API keys within your Admin Control Center Settings (`tab-config`). Standard billing hooks and direct payment checkouts dispatch through the backend endpoint proxy /functions/api/stripe-checkout.js. The endpoint contains rate limits targeting IP subnets to prevent malicious API exhaustion attacks.

Web3 Wallet Core (core/crypto.js)

Native checkout component <crypto-checkout> coordinates EVM (MetaMask, Coinbase, WalletConnect) and Solana (Phantom) browser handshakes directly. It validates signed challenge-response blocks securely and formats block hashes for display before dispatching token settlement orders (supporting stablecoins such as USDC, USDT alongside native coin balances).

7. SEO, RSS & Server Rules

Search Engine Optimization (SEO) and automated content syndication are critical to organic enterprise growth. Foundation manages this natively:

  • Dynamic Sitemap (/functions/api/sitemap.js): Serves /sitemap.xml on demand by aggregating static routes along with dynamic Firestore pages and CMS articles. Responses are edge-cached for high performance and contain search priority weights.
  • Broadcasting Feed (/functions/api/rss.js): Generates /rss.xml and /feed, conforming to standard RSS 2.0 and iTunes audio configurations (for podcast discovery). Features type-based feed filtering.
  • Zero-Build Server Deploy Templates: Root files pre-configure single-page routing structures and rewrites natively across multiple clouds, including Vercel (vercel.json), Netlify (netlify.toml), Nginx (nginx.conf), Apache (.htaccess), and IIS (web.config). These rule files rewrite feed targets and sitemaps cleanly directly into Cloudflare edge proxies.

8. Admin Control Center

Authenticated Administrators and Editors can access the core system dashboard at /admin.

The backoffice provides modular sections for Managing Site Configurations, setting Cloud API Credentials, drafting custom CMS Pages, updating Web Radio stream paths, toggling AdSense placements, tracking inventory stock limits, and triggering diagnostic workflow simulations.

🔑 Safety Lock Enforcement:

All developer console overrides or simulation flags configured locally (such as window.__FOUNDATION_DEV_BYPASS__ or store.state.devMode) are strictly isolated client-side and never propagate past server-verified Firestore rules or edge API session-token verifications. Security boundaries remain 100% active at all times.
